## 🌊 "오늘 사리예요" 한 줄로는 판단이 안 됩니다

이 앱의 출발점입니다. **같은 물때가 활동마다 정반대로 작용합니다.**

| 물때 | 물의 움직임 | 이 물때가 반가운 쪽 | 이 물때가 달갑지 않은 쪽 |
|---|---|---|---|
| **사리** | 물이 크게 움직이고 조류가 셉니다 | **갯벌체험** — 갯벌이 가장 넓게 드러나요 | **스킨스쿠버** — 물살이 세집니다 |
| **보통** | 물이 적당히 움직여요 | — | — |
| **조금** | 물이 거의 안 움직여요 | 물속에서 노는 활동 | **낚시** — 입질이 약해요 |

그래서 이 앱은 **물때 등급으로 활동을 자체 판정하지 않습니다.** 파고·수온·풍속까지 반영해서
국립해양조사원이 활동별로 따로 내는 **생활해양예보지수**를 그대로 가져와 보여줍니다.
물때는 물때대로, 활동 판단은 정부 예보대로 — 두 층을 겹쳐놓은 구조예요.

### 활동 9종

| 활동 | 지점 수 | 지수와 함께 보여주는 값 | 물 들어오는 시각 |
|---|---|---|---|
| 갯바위낚시 | 49 | 파고 · 수온 | |
| 선상낚시 | 49 | 파고 · 수온 | |
| 갯벌체험 | 18 | 체험 가능 시간대 | ✅ 갯벌 지점 기준 |
| 해수욕 | 49 | 파고 · 수온 · 개장 여부 | ✅ 관측소 간조 기준 |
| 스킨스쿠버 | 18 | 파고 · 수온 | ✅ 관측소 간조 기준 |
| 서핑 | 18 | 파고 · 수온 · 난이도 | |
| 바다여행 | 29 | 파고 · 수온 | |
| 뱃멀미 | 30 | 파고 | |
| 바다갈라짐 | 11 | 건널 수 있는 시간대 | ✅ 갈라짐 지점 기준 |

낚시 49곳은 갯바위·선상이 같은 지점표를 공유해요(같은 API를 `gubun`만 바꿔 부릅니다).
겹치는 것을 하나로 세면 **전국 222곳**입니다.

**20km 안에 지점이 없는 활동은 칩 자체를 숨깁니다.** 관측소 166곳 기준으로 20km 안에 활동 지점이
하나라도 있는 곳이 **151곳**이라, 반경을 5km로 좁히면 절반(89곳)이 빈 화면이 됩니다. 20km가
"빈 화면"과 "너무 먼 지점"이 둘 다 견딜 만해지는 지점이었어요.

## 📐 사리·조금을 음력이 아니라 **조차 백분위**로 판정합니다

물때를 세는 전통 방식(N물)은 음력 기준인데, **지역마다 기준이 다릅니다** — 서해는 7물때식,
남해 쪽은 8물때식이라 같은 날이 지역에 따라 다른 물때 숫자가 됩니다. 우리 화면은 전국 166곳을
한 앱에서 다루니, 지역 기준을 타는 숫자를 쓰면 어딘가는 반드시 틀립니다.

대신 데이터에 이미 들어 있는 값을 씁니다. **그날의 조차 = 그날 최고 만조 − 최저 간조.**
관측소마다 연중 조차 분포가 다르니, 그 관측소 자기 분포 안에서 어디쯤인지로 판정합니다.

| 판정 | 기준 |
|---|---|
| **사리** | 그날 조차 ≥ 그 관측소 연중 조차 **p75** |
| **조금** | 그날 조차 ≤ 그 관측소 연중 조차 **p25** |
| **보통** | 그 사이 |

기준선 p25·p75는 `scripts/build-stations.mjs` 로 미리 구워둡니다.

- 지점 코드마다 **15일 간격 표본**(연 24~25일)으로 조석예보를 받아 그날 조차를 모으고, 정렬해서 25/75 백분위를 뽑습니다.
- 하루 걸러 365일을 다 부르지 않는 이유: **조석은 천문학적으로 결정**돼서 15일 표본으로도 그 지점의 연중 분포를 대표할 수 있고, 해가 바뀌어도 거의 안 변합니다.
- 결과는 `src/lib/stations-index.ts` 에 `[지점코드, 이름, 위도, 경도, p25, p75]` 166행으로 커밋됩니다.
- 앱이 런타임에 받는 건 **그날의 만조·간조 시각뿐**입니다.

## 🚢 뱃멀미만 문구를 따로 만들었습니다

API가 주는 등급값(매우좋음~매우나쁨)은 9종이 전부 같은 5단계입니다. 그런데 뱃멀미는
**겪고 싶지 않은 증상**이라 다른 8종의 틀을 그대로 쓰면 이렇게 됩니다:

> ❌ "오늘 뱃멀미하기 좋아요"

방향이 뒤집혀 읽히죠. 그래서 뱃멀미만 "멀미하기 쉬운 정도"로 다시 씁니다.

| 등급 | 다른 활동 (예: 서핑) | 뱃멀미 |
|---|---|---|
| 매우좋음 | 오늘 서핑하기 아주 좋아요 | 오늘 배 타기 아주 편안해요 |
| 보통 | 오늘 서핑하기 무난해요 | 오늘 배가 조금 흔들려요 |
| 매우나쁨 | 오늘 서핑하기 좋지 않아요 | 오늘 배 타면 멀미하기 아주 쉬워요 |

`npm run check:activities` 는 이 방향이 뒤집히지 않았는지를 검사합니다 — 좋은 등급 문구에
"멀미"가 들어가거나, 나쁜 등급 문구에 안 들어가면 실패합니다.

## 🛟 안전은 단정하지 않고, 기준을 밝힙니다

물이 들어오면 위험해지는 활동(**갯벌체험 · 해수욕 · 스킨스쿠버 · 바다갈라짐**)에는
언제까지 나와야 하는지를 같이 띄웁니다.

| 활동 | 시각의 출처 | 화면 문구 예 |
|---|---|---|
| 갯벌체험 | 지수 응답의 체험 종료 시각 | `백사마을 갯벌 기준 · 18:00 무렵부터 물이 들어와요` |
| 바다갈라짐 | 지수 응답의 갈라짐 종료 시각 | `대섬 기준 · 18:00 무렵부터 길이 잠겨요` |
| 해수욕 · 스킨스쿠버 | 물때표의 **다음 간조** | `사초항 기준 · 15:09 간조 이후부터 물이 들어와요` |

**"어디 기준인지"를 문구에 반드시 넣습니다.** 갯벌 지점과 조석관측소는 서로 다른 곳이라
시각이 다릅니다 — 안 밝히면 두 시각을 헷갈려서 고립 사고로 이어질 수 있어요.

늦은 밤에 켜서 오늘 간조가 이미 다 지났으면 **내일 첫 간조**로 넘기고, 문구에 "내일"임을 밝힙니다.

**이안류**는 예보가 아니라 실측치라 성격이 다릅니다(전국 10곳, 6~9월만 서비스).
해수욕·스킨스쿠버를 골랐고 20km 안에 관측 지점이 있을 때만 붙고, **경계·위험일 때만** 붉게
강조합니다 — 관심·주의까지 매번 강조하면 사람들이 경고 자체를 무시하게 되니까요.

어떤 화면에도 **"안전합니다" 같은 단정은 쓰지 않습니다.** 대신 출처와 한계를 상시로 답니다.

> 국립해양조사원 조석예보 기준이에요. 실제 바다는 바람·기압에 따라 달라질 수 있어요.

## 📡 데이터와, 여기서 겪은 함정들

전부 **국립해양조사원** 공공데이터(공공데이터포털 경유)입니다. 백엔드 없이 브라우저가 직접 부릅니다.

| 데이터 | 엔드포인트 | 쓰는 곳 |
|---|---|---|
| 조석예보(고·저조) | `tideFcstHghLw/GetTideFcstHghLwApiService` | 만조·간조 시각·조위, 사리/조금 기준선 굽기 |
| 생활해양예보지수 9종 | `fcstFishingv2` · `fcstMudflatv2` · `fcstBeachv2` · `fcstSkinScubav2` · `fcstSurfingv2` · `fcstSeaTripv2` · `fcstSicknessv2` · `fcstSeaSplitv2` | 활동별 오늘 여건 |
| 이안류 지수 | `ripCurrent/GetRipCurrentApiService` | 해수욕·스킨스쿠버 위험 경고 |

**1. `www.khoa.go.kr` 직접 주소는 브라우저에서 못 씁니다.**
data.go.kr 상세페이지가 안내하는 기관 직접 호출 주소(`www.khoa.go.kr/oceandata/odmiapi/...`)는
CORS가 막혀 있습니다. 서버 없는 앱이라 여기서 한 번 막혀 프록시를 두는 우회 설계까지 갔는데,
**같은 API의 공공데이터포털 게이트웨이 주소**가 그냥 열려 있었습니다.

```
https://apis.data.go.kr/1192136/{path}/{Operation}?serviceKey=...&type=json
```

`{path}/{Operation}` 값은 추측이 아니라 data.go.kr 오퍼레이션 페이지 HTML 안에 인라인으로
박혀 있는 Swagger JSON(`const swaggerJson = ...`)에서 그대로 뽑았습니다.

**2. 오퍼레이션 이름이 대문자로 시작합니다.**
조석예보는 `GetTideFcstHghLwApiService` 입니다. REST 관례대로 소문자로 짐작해 만든 이름들은
전부 실패했고(열네 번을 헛짚었습니다), 결국 참고문서 탭의 HWP 활용가이드를 직접 파싱해서
확인했습니다 — CFB(OLE 복합문서)에서 `BodyText/Section0` 스트림을 raw deflate로 풀고
레코드 태그 67의 UTF-16LE 본문을 읽는 방식입니다. 이안류의 `beachCode` 값이 코드가 아니라
영문 문자열(`HAE`, `GYEONGPO` …)이라는 것도 같은 방법으로 알아냈습니다.

**3. 지점 코드가 옵션이라, 부르면 전국이 한 번에 옵니다.**
지수 8종은 place 코드 없이 부르면 전국 7일치가 통째로 옵니다(합계 약 1.6MB, 낚시가 70%).
그래서 **지점 좌표표는 미리 구워두고**(`scripts/build-activity-points.mjs` → `src/lib/activity-points.ts`),

- "이 근처에 지점이 있는지"는 미리 구운 표로 **즉시** 판정하고,
- 실제 지수는 **칩을 고른 활동만, 하루에 한 번만** 부릅니다(`localStorage` 캐시, 어제 이전 것은 정리).
- 새로 받다가 실패하면 예전 값이라도 보여주고, 화면에 그 값의 날짜를 같이 찍습니다.

**4. 이안류는 하루 5분 간격 실측이라 한 곳만 283건(0.63MB)입니다.**
"지금 위험도"만 필요하니 `totalCount`를 먼저 확인해 **마지막 한 건만** 받습니다.
비시즌(10~5월)엔 `totalCount`가 0인데, 이건 에러가 아니라 정상이라 조용히 숨깁니다.

**5. 인증키는 번들에 들어갑니다.**
서버를 두지 않는 대가로 감수한 절충입니다. 남용 방지는 공공데이터포털의 트래픽 제한에 맡깁니다.

지도 배경은 **OpenStreetMap** 타일입니다(인증키·도메인 등록 불필요). 타일이 한 장도 안 뜨면
지도를 붙잡고 있지 않고 목록형으로 되돌립니다.

## 📺 광고

| 자리 | 형태 | 갱신 |
|---|---|---|
| 화면 하단 고정 (앱 전체 1개) | 문구 강조형 배너 | 30초 |
| 본문 맨 아래 (물때표를 다 본 뒤) | 이미지 강조형 배너 | 30초 |

30초인 이유: 토스 배너는 AdMob 기반이고, **AdMob은 30초보다 잦은 갱신을 무효 트래픽으로 봅니다.**
더 짧게 잡으면 수익보다 제재 위험이 커져요. 화면이 가려져 있는 동안(`visibilitychange`)에는
갱신을 멈춥니다 — 노출로 잡히지도 않으면서 호출만 쌓이니까요.

이미지형 자리는 소재가 잘리지 않게 고정 높이가 아니라 **최소 높이**로 잡았고, 하단 고정 배너는
반대로 고정 높이입니다(위로 자라면 본문을 덮어요). 광고그룹 ID가 비어 있으면 하단 배너는 자리
자체를 만들지 않습니다 — 안 그러면 브라우저 개발 중에 흰 여백만 96px 깔립니다.

리워드 광고·인앱결제는 없습니다.

## 🚀 개발

```bash
npm install
touch .env                     # 아래 변수 4개를 채워요
npm run dev                    # 브라우저 (광고는 자리 자체가 안 생겨요)
npm run check:tide             # 물때 판정 · 시각 계산 자체 점검
npm run check:activities       # 활동 문구 · 20km 지점 매칭 자체 점검
npm run typecheck
npm run build                  # vite build + ait build → muldae.ait
npm run deploy
```

`.env` 에 필요한 변수 이름은 네 개입니다 — 값은 각자 발급받아 채우세요.

| 변수 | 쓰임 |
|---|---|
| `VITE_DATA_KEY` | 공공데이터포털 인증키 (앱 런타임) |
| `KHOA_KEY` | 같은 인증키 — `build-stations.mjs` 배치용 |
| `VITE_AD_GROUP_ID_BANNER` | 하단 고정 배너 지면 |
| `VITE_AD_GROUP_ID_BANNER_IMAGE` | 본문 이미지형 배너 지면 |

광고 ID를 비워두면 배너 자리가 아예 안 생겨서 브라우저 개발이 끊기지 않습니다.
`VITE_` 변수는 빌드 시점에 번들로 구워지니 값을 바꾸면 반드시 다시 빌드하세요.

> 조사 원본(`data/`)과 스크린샷(`screenshots/`)은 용량이 커서 저장소에 올리지 않습니다.
> 지점표를 다시 구우려면 `npm run stations` 과 `node scripts/build-activity-points.mjs` 를 쓰세요.
